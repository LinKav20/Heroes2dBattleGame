# Словарь

Единый словарь проекта. В документах, коде и интерфейсе каждое понятие называется только так, как здесь. Если нужного термина нет, его сначала добавляют сюда.

Обновлено: 2026-10-03.

## Бой и правила

| Термин | В коде | Значение |
|---|---|---|
| Бой | `Battle` | Одно сражение от расстановки до победы одной из сторон. |
| Сторона | `Side` | Команда в бою, например «атакующие» и «обороняющиеся». |
| Юнит | `Unit` | Фигура на поле. Это одно существо или отряд. |
| Отряд | `Unit` с `count > 1` | Юнит из нескольких одинаковых существ. Хранит количество существ и здоровье верхнего. Одиночное существо — отряд из одного. |
| Герой | `Hero` | Командир стороны. В зависимости от набора правил стоит вне поля и колдует или сражается на поле. |
| Активация | `Activation` | Момент, когда юнит получает право действовать. |
| Раунд | `Round` | Цикл, за который каждый юнит получает активацию. |
| Набор правил | `Ruleset` | Описание базовых механик боя: порядок ходов, что можно сделать за активацию, как бросаются кубики, роль героя. |
| Эффект | `Effect` | Изменение, наложенное на юнит, сторону или поле: бонус, штраф, статус, аура. |
| Статус | `Effect` с полем `ui` | Эффект, который показывается игроку иконкой. |
| Тег | `Tag` | Иерархическая метка вида `Status.Debuff.Poisoned`. Через теги работают статусы, типы существ, иммунитеты и запреты. |
| Операция | `Op` | Действие из фиксированного словаря движка: нанести урон, наложить эффект, призвать существ и так далее. Контент собирает поведение из операций. |
| Способность | `Ability` | То, что юнит может активировать: атака, выстрел, заклинание, умение, использование предмета. |
| Предмет | `Item` | Оружие, броня, артефакт, зелье, расходник. |

## Контент и сценарии

| Термин | В коде | Значение |
|---|---|---|
| Пак контента | `Pack` | Набор данных: наборы правил, существа, предметы, эффекты, сценарии, переводы. Паки подключаются и дополняют друг друга. |
| Реестр контента | `ContentRegistry` | Все загруженные и проверенные определения из паков. После загрузки не меняется. |
| Сценарий | `Scenario` | Описание конкретного боя: поле, препятствия, стороны, юниты, триггеры, условия победы. |
| Поле | `Field` | Гексагональная карта боя с препятствиями и опасными зонами. |
| Триггер сценария | `ScenarioTrigger` | Правило вида «событие, условие, действия», например подкрепление на третьем раунде. |
| Конфигурация боя | `BattleSetup` | То, что нужно для запуска боя: ссылка на сценарий, параметры участников, места и агенты, настройки. Её передаёт хост или создаёт сам клиент. |
| Результат боя | `BattleResult` | Итог боя для хоста: исход, итоговое состояние юнитов, потери, расход предметов. |

## Симуляция и история

| Термин | В коде | Значение |
|---|---|---|
| Ядро | `kernel` | Чистый детерминированный код правил и симуляции. Не знает про сеть, хранилище и отрисовку. |
| Состояние боя | `BattleState` | Полное состояние боя в виде JSON. |
| Команда | `Command` | Намерение участника: «походить», «атаковать», «ждать», «ответить на запрос решения». |
| Событие | `BattleEvent` | Свершившийся факт с результатом: «юнит прошёл по пути», «нанесено 14 урона, погибло 3 существа». |
| Пакет событий | `EventBatch` | Все события, которые породила одна команда. Имеет порядковый номер. |
| Шаг | `Step` | Часть выполнения команды: пройти путь, атаковать, ответный удар, проверить погибших. |
| Стек шагов | `Step[]` | Оставшиеся шаги текущей команды. Хранится в состоянии боя. |
| Запрос решения | `Decision` | Остановка ядра в ожидании ввода: бросок кубика, выбор цели, решение мастера. |
| Журнал | `Journal` | Упорядоченная запись всех команд и их пакетов событий. По журналу бой можно воспроизвести шаг за шагом. |
| Контрольная точка | `Snapshot` | Сохранённое состояние боя на определённом номере журнала. Ускоряет пересборку. |
| Откат | `Rewind` | Возврат боя к более раннему номеру журнала. Записывается в журнал как событие, история не стирается. |
| Повтор | `Replay` | Пошаговое проигрывание журнала без выполнения правил. |

## Участники и синхронизация

| Термин | В коде | Значение |
|---|---|---|
| Источник истины | `Authority` | Единственный, кто принимает команды боя, вызывает ядро и назначает номера пакетам. Бывает локальным (в клиенте) или серверным. |
| Реплика | `Replica` | Копия состояния боя у участника, который не является источником истины. Только применяет готовые события. |
| Эпоха | `epoch` | Номер, который растёт при смене источника истины. Защищает от двух источников истины одновременно. |
| Сессия боя | `BattleSession` | Объект, который связывает на одном устройстве источник истины или реплику, участников, хранилище и отображение. |
| Участник | `Participant` | Кто-то, подключённый к бою: мастер, игрок, бот, наблюдатель. У участника есть место (или нет, если он только смотрит), агент и канал. |
| Место | `Seat` | Право управлять одной или несколькими сторонами или отдельными юнитами. Как место за столом. |
| Агент | `Agent` | Тот, кто принимает решения за место: человек через интерфейс, ИИ, языковая модель, внешний бот. |
| Зритель | `Viewer` | Тот, для кого строится срез: мастер, игрок, наблюдатель. |
| Срез | `Projection` | Состояние и события глазами конкретного зрителя. Мастер видит всё, игрок видит только то, что ему положено. |
| Канал | `Channel` | Двусторонняя связь участника с источником истины: в памяти, WebSocket, postMessage. |

## Отображение

| Термин | В коде | Значение |
|---|---|---|
| Проигрыватель | `EventPlayer` | Показывает пакеты событий по очереди с анимациями. |
| Отображаемое состояние | `DisplayedState` | То, что сейчас нарисовано на экране. Догоняет истинное состояние по мере показа событий. |
| Метка анимации | `cue` | Идентификатор визуального эффекта в событии, например `attack.melee.sword`. |
| Манифест оформления | `SkinManifest` | Сопоставление существ, статусов и меток анимаций с картинками, анимациями и звуками. |
| Отрисовщик | `Renderer` | Модуль, который рисует поле и юниты: PixiJS, SVG или вообще ничего в тестах. |

## Архитектура

| Термин | В коде | Значение |
|---|---|---|
| Порт | `interface` в `application` | Интерфейс, через который приложение общается с внешним миром. Принадлежит приложению. |
| Адаптер | пакет в `adapters/` | Реализация порта под конкретную технологию: IndexedDB, WebSocket, PixiJS. |
| Реестр расширений | `Registry` | Таблица «идентификатор → реализация» для наборов правил, операций, агентов, отрисовщиков, каналов. Заполняется при запуске и потом не меняется. |
| Точка сборки | `compose*` | Функция в приложении, которая выбирает адаптеры и собирает систему. |
| Профиль | `Profile` | Готовый набор адаптеров для режима работы: «один мастер», «встроенный», «сетевой клиент», «сервер». |
| Хост | — | Внешнее приложение, которое встраивает наш клиент, например DnD. |
| Мост хоста | `HostBridge` | Адаптер общения с хостом: принимает конфигурацию боя, отдаёт результат и журнал. |
