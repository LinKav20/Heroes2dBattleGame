# 0007. Каждый бросок — запрос решения с политикой

Чтобы физические и цифровые кубики работали одинаково, мы оформляем каждый случайный исход как запрос решения «бросок» с политикой «цифровой / мастер / владелец», принимая лишний шаг для цифровых бросков.

## Контекст и проблема

Мастер хочет бросать некоторые кубики физически. Игроки могут бросать за своих юнитов. Остальное удобнее бросать цифровым генератором. Нужно, чтобы откат не позволял перебросить кубик.

## Рассмотренные варианты

1. Генератор внутри правил, ручной ввод — особый случай. Два пути в коде.
2. Все броски вводятся вручную. Слишком медленно для боя в духе Героев.
3. Каждый бросок — запрос решения; политика определяет, кто отвечает.

## Решение

Мы выбираем третий вариант. Политика задаётся в наборе правил для каждого назначения броска и может быть переопределена в конфигурации боя. При цифровой политике источник истины сам отвечает значением из генератора, который хранится в состоянии боя. В журнал пишутся значения и кто бросал.

## Последствия

- Хорошо: один путь в коде; любой бросок можно сделать ручным настройкой.
- Хорошо: генератор восстанавливается при откате, переброс невозможен.
- Плохо: цифровые броски проходят через лишний шаг; на производительность пошаговой игры это не влияет.

## Как проверяем

Тест: один и тот же бой с цифровыми бросками и с ручным вводом тех же значений даёт одинаковый журнал событий.
