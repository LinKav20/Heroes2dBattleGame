# 0003. Чистое детерминированное ядро на TypeScript

Чтобы правила работали одинаково в браузере, на сервере, в ботах и тестах, мы пишем ядро как чистые детерминированные функции на TypeScript, принимая запрет на случайность, время и дробную арифметику внутри ядра.

## Контекст и проблема

Один и тот же бой должен давать одинаковый результат при повторе, на сервере и у реплик. ИИ должен перебирать варианты, вызывая правила на копии состояния. Тесты должны работать без браузера.

## Рассмотренные варианты

1. Правила внутри интерфейса или игрового фреймворка. Нельзя запустить на сервере и в тестах.
2. Разные реализации правил для клиента и сервера. Неизбежные расхождения.
3. Одно чистое ядро, которое работает везде.

## Решение

Мы выбираем третий вариант. Ядро — две функции: «состояние и команда дают события» и «состояние и событие дают новое состояние». В ядре нет DOM, API Node, `Math.random`, текущего времени и дробных чисел в игровой арифметике. Случайность — генератор, состояние которого хранится в состоянии боя. Время приходит как данные.

## Последствия

- Хорошо: один код правил везде; воспроизводимость; простые тесты.
- Хорошо: ИИ использует ядро для перебора вариантов.
- Плохо: нужна дисциплина: целочисленная арифметика, детерминированный порядок обхода, явная передача всех входов.

## Как проверяем

Линтер запрещает в ядре `Math.random`, `Date.now`, DOM и API Node. Эталонные журналы повторяются в браузере, Web Worker и Node.js с сравнением хешей.
