# 0008. Сервер — одно приложение на Node.js

Сервер делаем одним процессом на Node.js из тех же пакетов, что и клиент, с WebSocket и PostgreSQL. Так сетевой бой использует те же правила и не требует сложной инфраструктуры. Цена — каждый бой обслуживает один процесс.

## Задача

Для сетевой игры нужен арбитр на сервере. Команда небольшая, а правила дублировать нельзя.

## Варианты

1. Сервер на другом языке с переписанными правилами. Получится два движка, и они разойдутся.
2. Микросервисы. Для нашего масштаба это лишнее.
3. Один процесс на Node.js из тех же пакетов, что и клиент.

## Решение

Выбираем третий вариант. Сервер — это приложение `apps/server`, точка сборки с адаптерами PostgreSQL и WebSocket и серверной политикой доступа. С акторами сервер общается по WebSocket. Если одного процесса станет мало, бои распределяются между процессами по номеру боя.

## Последствия

Прикладная логика и ядро общие с клиентом, а инфраструктура простая.

Для долгих соединений нужен хостинг, который их поддерживает.

## Как проверяем

Сценарные тесты прогоняются на серверной сборке. CI проверяет, что в сборку сервера не попали пакеты интерфейса.
