# 0014. Встраивание через iframe и протокол сообщений

Чтобы хост мог запустить бой, ничего не зная о нашем коде, а мы не зависели от устройства хоста, мы встраиваемся через iframe и общаемся с хостом опубликованным версионированным протоколом сообщений postMessage, принимая ограничения iframe.

## Контекст и проблема

Хост, например DnD, хочет открыть бой у себя, передать параметры участников и получить результат. У хоста свой стек, свои стили и свой цикл выпуска.

## Рассмотренные варианты

1. npm-пакет, который хост подключает в свой код. Конфликты зависимостей и стилей, хост обновляется вместе с нами.
2. Хост сам рисует бой, мы даём только логику. Много работы у хоста.
3. iframe с протоколом сообщений. Полная изоляция, общение только через документированные сообщения.

## Решение

Мы выбираем третий вариант. Протокол: `ready`, `createBattle`, `resumeBattle`, `openReplay`, `battleStarted`, `battleProgress`, `battleFinished`, `getJournal`, `journal`, `error`. Конфигурация и результат боя описаны JSON-схемами. Перевод данных хоста делает хост. Для сетевого боя дополнительно есть HTTP API сервера.

## Последствия

- Хорошо: полная изоляция; хосты на любом стеке.
- Плохо: ограничения iframe по размерам и фокусу; нужно следить за безопасностью сообщений.

## Как проверяем

Пример хоста в репозитории работает только через протокол. Тесты проверки `origin` и схем сообщений.
