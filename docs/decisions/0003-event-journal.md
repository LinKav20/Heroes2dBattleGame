# 0003. История боя — журнал событий

Бой храним журналом команд и событий вместе с их результатами. Так бой можно пересмотреть по шагам, откатить и передать хосту. Цена — формат событий придётся версионировать.

## Задача

Нужно пересматривать каждый шаг, откатываться к любому шагу, продолжать бой после перезагрузки, держать одинаковое состояние во всех копиях боя и отдавать историю хосту. Если хранить только текущее состояние, ничего из этого не получится.

## Варианты

1. Хранить текущее состояние и делать снимки, когда нужно. Нет ни истории, ни возможности проверить, что происходило.
2. Хранить только команды и при повторе считать правила заново. Повтор сломается, как только поменяются правила, и кубики придётся бросать снова.
3. Хранить команды и события с результатами, а для скорости делать снимки.

## Решение

Выбираем третий вариант. Журнал только дополняется. В каждой записи — номер, эпоха, команда, идентификатор отправившего её актора, пакет событий и хеш состояния. События хранят результаты, поэтому при повторе правила не считаются и кубики не бросаются. Откат — это новая запись, история не стирается.

Отдельная база для чтения не нужна: проекции строятся из состояния в памяти.

## Последствия

Просмотр, откат, проверка, передача хосту и синхронизация копий боя работают на одном механизме.

Формат событий придётся версионировать и поддерживать миграции. Журнал растёт, поэтому нужны снимки.

## Как проверяем

Тест сравнивает состояние после повтора журнала с состоянием живого боя. Отдельные тесты прогоняют миграции на журналах старых версий.
