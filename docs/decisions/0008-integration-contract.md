# 0008. Интеграция через контракт и сменные адаптеры

Внешние системы используют бой через один опубликованный контракт интеграции. Потребитель подключает библиотеки напрямую или работает через адаптер интеграции, который реализует конкретный способ связи: iframe, HTTP или любой другой. Написать такой адаптер может кто угодно. Так движок встраивается куда угодно и не зависит ни от одного потребителя. Цена — контракт придётся версионировать и сохранять его совместимость.

## Задача

Бой нужен в очень разных местах. Наша собственная тактическая игра хочет, чтобы бой был просто частью её приложения. Сервис настольной ролевой игры на другом стеке хочет встроить бой к себе на страницу. Серверной системе нужен HTTP. Каких ещё интеграций захотят другие, заранее не знает никто.

## Варианты

1. Один способ интеграции, например только iframe. Наша собственная игра вынуждена общаться с боем сообщениями, хотя могла бы вызывать его напрямую, а каждый новый способ требует правок движка.
2. Только библиотека, которую потребитель подключает к своему коду. Потребителю на другом стеке это неудобно, а стили и зависимости конфликтуют.
3. Один контракт интеграции и сколько угодно адаптеров поверх него.

## Решение

Выбираем третий вариант.

Контракт интеграции — это входящие порты `BattleHosting` и `BattlePlay` вместе с форматами из библиотеки `protocol`: конфигурацией боя, результатом, журналом и настройками экрана. `BattleHosting` позволяет создать бой, продолжить его, прервать, открыть запись, получить результат и журнал и подписаться на этапы жизни боя. У контракта есть версия, а форматы опубликованы в виде JSON Schema.

При прямом подключении потребитель вызывает входящие порты сам, без адаптера. Для остальных способов адаптер интеграции переводит контракт на конкретный способ связи и сам ничего не решает. Готовые адаптеры:

- iframe с сообщениями `postMessage`;
- HTTP API сервера боёв;
- автономный запуск без потребителя.

Новый способ — новый адаптер. Контракт, прикладная логика и ядро при этом не меняются.

## Последствия

Наша собственная игра подключает бой как часть приложения, сервисы на другом стеке встраивают его через iframe, серверные системы обращаются к серверу по HTTP. Адаптеры для новых способов интеграции пишутся без правок движка, в том числе сторонними разработчиками.

Контракт становится публичным, поэтому его нужно версионировать и не ломать без новой версии. У каждого адаптера свои заботы: например, у iframe — проверка `origin` и ограничения по размерам и фокусу.

## Как проверяем

У контракта есть общий набор тестов, и каждый адаптер интеграции его проходит. Примеры потребителей для прямого подключения и для каждого готового адаптера работают только через контракт. Тест сравнивает выгруженные схемы контракта с сохранёнными в репозитории, чтобы несовместимое изменение не прошло незамеченным.
