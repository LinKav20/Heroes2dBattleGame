# Журнал решений

Архитектурные решения проекта, по одному в файле.

Обновлено 5 октября 2026.

Каждое решение оформляется по [шаблону](template.md). Пока нет первой версии, решения правим прямо в файлах, а связанные объединяем, чтобы их было как можно меньше. После выпуска первой версии принятые решения перестанем редактировать: изменение будет оформляться новым решением, а старое — помечаться как заменённое.

| № | Решение | Коротко | Статус |
|---|---|---|---|
| [0001](0001-ports-adapters-microkernel.md) | Порты, адаптеры и микроядро | Центр общается с миром через порты, расширения подключаются через реестры, границы проверяет CI | Предложено |
| [0002](0002-deterministic-kernel.md) | Детерминированное ядро и ввод через запросы | Одно ядро для браузера, сервера, ИИ и тестов; ожидание ввода и броски — запросы в состоянии | Предложено |
| [0003](0003-event-journal.md) | История боя — журнал событий | Просмотр, откат и проверка без повторного расчёта правил | Предложено |
| [0004](0004-arbiter-and-access.md) | Один арбитр, безликие акторы и внешняя политика доступа | Клиент работает без сервера; права, видимость и роли решает внешняя политика, а не ядро | Предложено |
| [0005](0005-content-and-rules-as-data.md) | Контент и правила описываются данными | Паки в JSON, операции из реестра, модель правил, наборы правил, отряды, схемы TypeBox, свой редактор | Предложено |
| [0006](0006-event-driven-presentation.md) | Экран проигрывает события, а оформление описано отдельно | Ядро и контент не знают об экране; рендерер можно заменить, анимации можно пропустить | Предложено |
| [0007](0007-iframe-embedding.md) | Встраивание через iframe и сообщения | Хост не зависит от нашего кода | Предложено |
| [0008](0008-single-node-server.md) | Сервер — одно приложение на Node.js | Тот же код ядра, без микросервисов | Предложено |
