# 0015. Сервер — модульный монолит на Node.js

Чтобы сетевой бой использовал тот же код правил и не требовал сложной инфраструктуры, мы делаем сервер одним процессом Node.js, собранным из тех же пакетов, с WebSocket и PostgreSQL, принимая, что один бой обслуживает один процесс.

## Контекст и проблема

Для сетевой игры нужен источник истины на сервере. Команда небольшая. Правила не должны дублироваться.

## Рассмотренные варианты

1. Сервер на другом языке с переписанными правилами. Два движка, расхождения.
2. Микросервисы. Избыточно для масштаба проекта.
3. Один процесс Node.js из тех же пакетов, что и клиент.

## Решение

Мы выбираем третий вариант. Сервер — приложение `apps/server`: точка сборки с адаптерами PostgreSQL и WebSocket. Связь с участниками — WebSocket. Масштабирование при необходимости — распределение боёв по процессам по идентификатору боя.

## Последствия

- Хорошо: тот же прикладной слой и ядро; простая инфраструктура.
- Плохо: долгоживущие соединения требуют хостинга, который их поддерживает.

## Как проверяем

Сценарные тесты прогоняются против серверной сборки. Проверка, что в сборке сервера нет пакетов интерфейса.
