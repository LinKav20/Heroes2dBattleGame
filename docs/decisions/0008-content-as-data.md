# 0008. Контент как данные, поведение из реестра операций

Чтобы новые существа, предметы, эффекты и сценарии добавлялись без программирования и проверялись автоматически, мы описываем контент в JSON, а поведение собираем из операций, зарегистрированных в коде, принимая, что совсем новая механика требует новой операции.

## Контекст и проблема

Контента будет много, и его будут писать не только программисты. Контент должен проверяться, сериализоваться, передаваться по сети и одинаково исполняться везде.

## Рассмотренные варианты

1. Контент в коде. Каждое существо — программирование и сборка.
2. Скрипты внутри контента (Lua, JavaScript в песочнице). Гибко, но ломает детерминизм и проверку, непрозрачно для ИИ и интерфейса.
3. Чистые декларативные данные без ссылок на код. Быстро обрастает исключениями.
4. Данные, которые ссылаются на операции и условия из реестра.

## Решение

Мы выбираем четвёртый вариант. Контент — JSON в паках. Поведение — дерево операций (`{op: ...}`), условий и формул, где каждый узел выбирает реализацию из реестра. Произвольный код из контента не исполняется.

## Последствия

- Хорошо: контент проверяется схемами и по смыслу, понятен ИИ и редактору.
- Хорошо: детерминизм сохраняется.
- Плохо: для новой механики нужна новая операция в коде.

## Как проверяем

Проверка контента в CI: все ссылки на операции и условия разрешаются в реестре.
