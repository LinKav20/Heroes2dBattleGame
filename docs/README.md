# Документация

Здесь описано, как устроен движок тактических боёв: что он делает, из каких частей состоит и почему так.

Обновлено: 2026-10-03.

## Что где лежит

| Папка или файл | Что внутри | Когда читать |
|---|---|---|
| [architecture/](architecture/README.md) | Описание архитектуры: цели, контекст, части системы, сценарии работы, сквозные концепции, качество, риски, этапы | Чтобы понять систему целиком |
| [decisions/](decisions/README.md) | Архитектурные решения (ADR): одно решение в файле, с контекстом, вариантами и последствиями | Чтобы понять, почему сделано так, а не иначе |
| [reference/](reference/README.md) | Справочник: наброски типов, форматы сообщений, примеры JSON | Когда нужны точные поля и форматы |
| [glossary.md](glossary.md) | Словарь терминов | Всегда, если встретили незнакомое слово |

## Порядок чтения

1. [Обзор архитектуры](architecture/README.md): одна страница, даёт общую картину.
2. [Цели и ограничения](architecture/01-goals-and-constraints.md) и [контекст](architecture/02-context.md): что строим и с кем система взаимодействует.
3. [Стратегия решения](architecture/03-solution-strategy.md): ключевые идеи.
4. [Строительные блоки](architecture/04-building-blocks.md) и [сценарии работы](architecture/05-runtime.md): как части связаны и как они работают вместе.
5. Сквозные концепции и ADR — по мере необходимости.

## Как поддерживать

- Документация меняется в том же пулл-реквесте, что и код, который она описывает.
- Принятые ADR не редактируют. Если решение меняется, пишут новый ADR и помечают старый как заменённый.
- Термины берутся только из словаря.
- В каждом файле указана дата последнего обновления.
