# Встраивание в хост

Обновлено: 2026-10-03.

Кратко: хост открывает наш клиент в iframe, выбирает наш сценарий и передаёт параметры участников. Дальше бой целиком обслуживает наш клиент. Журнал и результат сохраняются у нас. Хост получает результат и по запросу журнал и сам решает, как изменить своё состояние. Хост общается с нами только по опубликованному протоколу сообщений и ничего не знает о нашем коде.

## Роли

| Сторона | Отвечает за |
|---|---|
| Хост | Выбор сценария, параметры участников (например, текущее здоровье после прошлого боя), кто из участников игрок, а кто бот, перенос результата в своё состояние |
| Наш клиент | Проверка конфигурации, запуск боя по сценарию, весь ввод и вывод во время боя, журнал, повтор и откат, результат |

Перевод данных хоста в нашу конфигурацию боя и обратно делает хост. Мы не подстраиваемся под форматы конкретных хостов.

## Точка встраивания

Хост открывает iframe по адресу точки встраивания, например `https://<наш-домен>/embed`. Клиент запускается в профиле `embedded` и общается с хостом через мост хоста (порт `HostBridge`, адаптер postMessage).

## Обмен сообщениями

| Сообщение | Направление | Когда |
|---|---|---|
| `ready` | клиент → хост | Клиент загрузился. Содержит версию протокола |
| `createBattle` | хост → клиент | Создать новый бой. Содержит конфигурацию боя |
| `resumeBattle` | хост → клиент | Продолжить сохранённый бой по идентификатору |
| `openReplay` | хост → клиент | Открыть завершённый бой для просмотра |
| `battleStarted` | клиент → хост | Бой создан. Содержит идентификатор боя |
| `battleProgress` | клиент → хост | Необязательно: номер раунда и шага, чтобы хост мог показать прогресс |
| `battleFinished` | клиент → хост | Бой окончен. Содержит результат боя |
| `getJournal` | хост → клиент | Запросить журнал |
| `journal` | клиент → хост | Журнал боя |
| `error` | клиент → хост | Ошибка конфигурации или выполнения со списком причин |

Форматы сообщений — в [reference/protocol.md](../../reference/protocol.md).

## Конфигурация боя

Хост передаёт:

- **Сценарий:** идентификатор нашего сценария.
- **Параметры участников** поверх данных сценария: текущее здоровье, действующие эффекты, инвентарь, потраченные использования способностей. Так последствия прошлых событий кампании переходят в бой.
- **Места и агентов:** какой стороной управляет мастер, какой — ИИ, какой — игрок (в сетевом бою).
- **Изменения набора правил,** например кто бросает кубики.
- **Настройки:** фиксированное зерно, политика отката, язык, оформление, скорость анимаций.
- **Метку хоста:** любая строка, например «кампания 42, сессия 7, встреча 3». Мы её не разбираем и возвращаем в результате, чтобы хост связал результат со своими данными.

Если конфигурация некорректна, хост получает `error` со списком причин, и бой не создаётся. Пример — в [reference/examples.md](../../reference/examples.md).

## Результат боя

Хост получает:

- исход: победа, поражение или ничья, победившие стороны, выполненное условие;
- число раундов;
- итоговое состояние каждого юнита: жив ли, сколько существ было и осталось, здоровье, действующие эффекты, изменения инвентаря, потраченные использования;
- призванных существ и потери;
- значения переменных сценария;
- хеш итогового состояния.

Журнал передаётся отдельно по запросу, потому что он может быть большим.

## Встраивание с сервером

Если нужен сетевой бой, хост создаёт его через HTTP API сервера и получает ссылки для каждого места. Ссылку мастера хост открывает у себя в iframe, ссылки игроков раздаёт игрокам. Результат и журнал доступны и через postMessage в iframe мастера, и через HTTP API сервера.

## Безопасность

- Наш хостинг отдаёт заголовок `Content-Security-Policy: frame-ancestors` со списком разрешённых хостов.
- Мост проверяет `origin` каждого входящего сообщения и отправляет сообщения только на точный адрес хоста, никогда на `*`.
- Каждое входящее сообщение проверяется по схеме протокола.
- Токены мест не попадают в журналы и логи.

## Версии протокола

У протокола встраивания своя версия. Клиент сообщает её в `ready`. Новые поля добавляются совместимо. Несовместимые изменения — новая версия протокола, старая поддерживается ограниченное время.
