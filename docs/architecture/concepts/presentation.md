# Отображение

Обновлено: 2026-10-03.

Кратко: ядро выполняет команду мгновенно, а показ результата занимает время. Проигрыватель показывает пакеты событий по очереди, а интерфейс рисует отображаемое состояние, которое догоняет истинное. События содержат метки анимаций, а какие картинки и звуки им соответствуют, решает манифест оформления. Отрисовщик заменяемый.

## Проигрыватель и отображаемое состояние

- Пакеты событий складываются в очередь. Проигрыватель берёт их по одному и показывает события по порядку.
- Интерфейс рисует отображаемое состояние. Оно обновляется по мере показа событий, поэтому полоса здоровья не падает раньше, чем прилетела стрела.
- События содержат значения «после изменения». Проигрывателю не нужно заглядывать в истинное состояние.
- После каждого пакета отображаемое состояние сверяется со срезом и выравнивается.

## Метки анимаций

У события может быть метка анимации, например `attack.melee.sword`. У метки есть режим:

| Режим | Поведение |
|---|---|
| Блокирующий | Следующий эффект ждёт окончания этого |
| Параллельный | Эффекты группы идут одновременно, например удар и всплывающий урон |
| Постоянный | Аура или иконка статуса держится, пока действует эффект |

Постоянные эффекты дополнительно выводятся из состояния. Поэтому после переподключения или перехода по журналу они на месте.

## Данные для отображения

- **Каталог контента:** имена, описания, характеристики, метки анимаций по умолчанию. Путей к ассетам в нём нет.
- **Манифест оформления:** принадлежит слою отображения. Сопоставляет существам спрайты и анимации, статусам — иконки, меткам — обработчики, ассеты и звуки. Для неизвестной метки есть обработчик по умолчанию.
- **Поле** из сценария.
- **Зритель:** мастер, игрок каких сторон или наблюдатель.
- **Срез состояния и пакеты событий,** уже отфильтрованные для зрителя.

## Ввод

- Наведение, выделение, открытие книги заклинаний остаются внутри интерфейса.
- Подсказки (доступные действия, досягаемость, путь, прогноз, очередь ходов) интерфейс получает через порт `BattlePlay`. Они считаются ядром на срезе.
- Действия игрока интерфейс отправляет как команды через своего агента.

## Скорость, пропуск, переподключение

- Скорость всех анимаций регулируется одним множителем.
- Пропуск мгновенно завершает все эффекты в очереди и выставляет отображаемое состояние равным последнему срезу.
- Можно включить «действие игрока прерывает анимацию» и «быстрые ходы ИИ».
- При переподключении применяется свежий срез, постоянные эффекты строятся из состояния, показываются только новые события.

## Отрисовщики

Порт `Renderer`: подключиться к элементу страницы, применить состояние, показать событие, мгновенно завершить событие, подсветить гексы, определить объект под курсором, освободить ресурсы.

| Адаптер | Где используется |
|---|---|
| PixiJS | Основной |
| SVG | Лёгкий режим, редактор |
| Без вывода | Тесты и симуляции: записывает метки анимаций и сразу завершает |

Интерфейс боя (очередь ходов, карточка юнита, панель действий, книга заклинаний, инвентарь, журнал, окна решений и ввода бросков) сделан на React и рисуется в DOM поверх поля. Он читает отображаемое состояние и к ядру напрямую не обращается.
