# Симуляция

Обновлено: 2026-10-03.

Кратко: ядро — чистые функции. Одна проверяет команду и превращает её в события, другая применяет событие к состоянию. Команда выполняется по шагам из стека. Когда шагу нужен ввод, ядро записывает запрос решения и останавливается. Любой случайный исход — такой запрос. Порядок ходов выбирается набором правил.

## Состояние боя

Состояние боя — обычный JSON. Оно хранит:

- версию формата, паки и хеш контента, набор правил;
- номер версии состояния, который растёт с каждым пакетом событий;
- раунд и фазу боя: расстановка, начало раунда, активация юнита, конец;
- стороны с героями и юниты с ресурсами, эффектами, тегами, флагами, инвентарём;
- поле с препятствиями и опасными зонами;
- переменные сценария и состояние его триггеров;
- стек шагов и текущий запрос решения;
- состояние генератора случайных чисел.

Определения из реестра контента в состояние не копируются, на них ведут ссылки.

## Функции ядра

Функции чтения не меняют состояние:

- перечислить доступные действия;
- найти досягаемые гексы и путь;
- посчитать прогноз действия: урон, потери, ответный удар, эффекты;
- построить очередь ходов на несколько раундов вперёд;
- вернуть текущий запрос решения;
- построить срез для зрителя.

Функции чтения работают и на срезе, поэтому клиент-реплика вызывает их у себя.

Функции записи:

- проверить команду и превратить её в события;
- применить событие к состоянию.

Проверка команды — это проверка, что она входит в список доступных действий. Прогноз и выполнение используют одни и те же расчёты. Поэтому если интерфейс показал «убьёт троих», ядро посчитает так же.

## Команды и события

Команда — намерение: расставить юнит, походить, атаковать, выстрелить, применить способность или предмет, ждать, обороняться, отступить, ответить на запрос решения, правка мастера, откат.

Событие — свершившийся факт с результатом. Оно хранит значения «после изменения»: сколько существ осталось, сколько здоровья у верхнего, какие выпали кубики. У события есть ссылка на причину, например ответный удар ссылается на атаку. Есть пометка видимости: для всех, для определённых сторон или только для мастера. Есть необязательная метка анимации.

Все события одной команды образуют пакет. Пакет атомарен и получает порядковый номер.

Полный список команд и событий — в [reference/types.md](../../reference/types.md).

## Стек шагов

Команда выполняется не одним куском. Ядро проверяет её и кладёт в стек шаги. Для атаки это: оплатить стоимость, пройти путь, атаковать, ответный удар, проверить погибших, пересчитать ауры, закончить активацию, проверить мораль, передать ход. Затем ядро по одному снимает шаги. Каждый шаг выдаёт события и может положить новые шаги.

Ответный удар, эффекты «при попадании» и триггеры — тоже шаги в этом стеке. Глубина стека и число шагов ограничены, чтобы цепочки триггеров не зациклились.

В шагах нет функций, только данные. Поэтому стек сохраняется вместе с состоянием.

## Запросы решений

Если шагу нужен ввод, ядро записывает запрос решения и останавливается. Виды запросов:

- бросок кубиков;
- выбор варианта;
- выбор цели;
- решение мастера.

У запроса есть вариант по умолчанию. Его применяют, если агент не ответил вовремя.

Бой можно сохранить, передать по сети или отдать управление другому агенту прямо в момент ожидания. Ответ приходит отдельной командой, ядро проверяет его и продолжает с того же шага.

## Кубики

Любой случайный исход оформляется как запрос решения «бросок». Кто бросает, задаётся для каждого назначения броска: атака, урон, мораль, инициатива и так далее.

| Политика | Кто бросает |
|---|---|
| Цифровой | Источник истины берёт значение из генератора в состоянии |
| Мастер | Значение вводит мастер |
| Владелец | Значение вводит игрок, управляющий юнитом |

Во всех случаях ответ приходит одинаковой командой, путь в коде один. В журнал пишутся значения и кто бросал.

Генератор хранится в состоянии. Поэтому после отката те же действия дают те же цифровые броски, и перебросить кубик через откат нельзя. В сетевом бою генератор есть только на сервере и в срезы не попадает.

## Порядок ходов

Очередь ходов не хранится, её пересчитывают после каждой активации. Поэтому замедление или ускорение посреди раунда сразу меняет порядок. Вариант выбирается набором правил.

**По скорости, как в Героях:**

- Раунд делится на фазы: осадные орудия; все юниты по убыванию скорости; ждавшие юниты с моралью; остальные ждавшие по возрастанию скорости.
- При равной скорости в первом раунде первыми ходят атакующие, дальше — сторона, которая не ходила последней, внутри стороны — по порядку в армии.
- Ждать можно раз за раунд.
- Оборона даёт бонус к защите до следующего хода юнита и отменяет дополнительный ход от морали.
- Плохая мораль проверяется в начале активации, хорошая — после действия и даёт не больше одного дополнительного хода.
- В начале раунда сбрасываются флаги ожидания, обороны, морали и счётчики ответных ударов.

**По инициативе, как в d20:**

- В начале боя бросается инициатива, порядок фиксируется на весь бой.
- Ничьи разрешаются по атрибуту из набора правил.
- За активацию доступны действие, перемещение и бонусное действие.

## Детерминизм

Правила для кода ядра:

- нет `Math.random`, текущего времени и дробных чисел в игровой арифметике;
- нет зависимости от порядка обхода `Map` и `Set`;
- идентификаторы назначаются детерминированно;
- одинаковый вход всегда даёт одинаковый результат в браузере, Web Worker и Node.js.

Это проверяется в CI: эталонные журналы повторяются и сравниваются по хешу состояния.
