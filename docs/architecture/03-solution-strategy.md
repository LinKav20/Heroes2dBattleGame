# 3. Стратегия решения

Обновлено: 2026-10-03.

Кратко: архитектура — гексагональная с микроядром. В центре чистое ядро правил и прикладной слой. Всё внешнее (хранилище, связь, источник истины, агенты, отрисовка, хост) подключается через порты и адаптеры. Расширения регистрируются в реестрах. Конкретный режим работы собирается в точке сборки из готового профиля.

## 3.1 Архитектурный стиль

Стиль складывается из пяти известных подходов. Каждый решает свою задачу.

**Гексагональная архитектура (порты и адаптеры).** Приложение общается с внешним миром только через интерфейсы, которые оно само объявляет. Это порты. Конкретные технологии реализуют порты, это адаптеры. Поэтому IndexedDB можно заменить на сервер, а WebSocket на postMessage, не трогая логику. Тесты — тоже адаптер.

**Микроядро.** Ядро содержит только механизм боя. Всё, что меняется часто, подключается как расширение через реестры: наборы правил, операции эффектов, условия, агенты ИИ, отрисовщики, каналы, хранилища. Контент ссылается на расширения по идентификатору.

**Функциональное ядро, императивная оболочка.** Ядро — чистые функции: «состояние и команда дают события», «состояние и событие дают новое состояние». Чтение, запись, сеть и время находятся в оболочке вокруг ядра.

**Журнал событий.** История боя хранится как последовательность команд и событий. По ней бой воспроизводится, откатывается и передаётся хосту. Для каждого зрителя строится свой срез. Отдельной базы для чтения нет: бой маленький и живёт в памяти.

**Один источник истины на бой.** В каждый момент команды принимает только один источник истины. По умолчанию он локальный, в клиенте. Если подключён сервер, источник истины переезжает на сервер, а клиенты становятся репликами. Смена источника истины помечается новой эпохой.

## 3.2 Как цели качества достигаются

| Цель качества | Подход | Подробности |
|---|---|---|
| Воспроизводимость | Чистое ядро без случайности и времени; генератор случайных чисел хранится в состоянии; события хранят результаты, повтор не вызывает правила | [concepts/simulation.md](concepts/simulation.md), ADR [0003](../decisions/0003-pure-deterministic-kernel.md), [0004](../decisions/0004-event-journal.md) |
| Расширяемость | Порты и адаптеры, реестры расширений, профили в точке сборки, автоматическая проверка зависимостей | [04-building-blocks.md](04-building-blocks.md), ADR [0002](../decisions/0002-hexagonal-microkernel.md), [0018](../decisions/0018-dependency-rules-enforced.md) |
| Автономность | Локальный источник истины и локальное хранилище по умолчанию; сервер — необязательный адаптер | [concepts/authority-and-sync.md](concepts/authority-and-sync.md), ADR [0005](../decisions/0005-movable-single-authority.md) |
| Честность | Все команды проверяются ядром у источника истины; срезы для зрителей строятся и для состояния, и для событий; на сервере генератор случайных чисел не покидает сервер | [concepts/authority-and-sync.md](concepts/authority-and-sync.md), ADR [0012](../decisions/0012-viewer-projections.md) |
| Встраиваемость | iframe и опубликованный протокол сообщений; хост работает только с конфигурацией боя и результатом | [concepts/host-integration.md](concepts/host-integration.md), ADR [0014](../decisions/0014-iframe-embedding.md) |
