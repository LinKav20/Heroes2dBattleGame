# 1. Цели и ограничения

Обновлено: 2026-10-03.

Кратко: движок должен проводить бои в духе Героев 3 по правилам из данных, работать без сервера и подключать сервер, ботов и внешние приложения без изменения ядра. Главные качества — воспроизводимость, расширяемость и автономность клиента.

## 1.1 Что система делает

- Загружает паки контента: наборы правил, существ, героев, предметы, эффекты, поля боя, сценарии. Проверяет их.
- Запускает бой по сценарию и конфигурации боя.
- Принимает команды участников, проверяет их по правилам и выполняет.
- Показывает бой: поле, юниты, статусы, анимации действий, подсказки по доступным действиям.
- Ведёт полный журнал боя, позволяет проиграть его по шагам и откатить к любому шагу.
- Работает в нескольких режимах:
  - один мастер за одним экраном;
  - встроенный в хост через iframe;
  - сетевой, когда участники сидят на своих устройствах, а сервер синхронизирует состояние.
- Отдаёт хосту результат боя и журнал.
- Даёт редактор для сценариев и контента.

## 1.2 Цели

1. Бои в духе Героев 3: гексагональное поле, отряды, порядок ходов по скорости, ожидание, оборона, ответные удары, стрельба, заклинания, мораль.
2. Гибкие правила: тот же движок проводит бой по правилам d20 (инициатива, действие и перемещение за ход), если это задано набором правил.
3. Всё, что можно описать данными, описывается данными.
4. Клиент работает полностью без сервера.
5. Новые способы хранения, связи, ИИ, отрисовки и встраивания добавляются новым адаптером без изменения ядра и приложения.
6. Хост встраивает бой, ничего не зная о нашем коде.

## 1.3 Не-цели

- Бои в реальном времени. Только пошаговые.
- Глобальная карта, города, экономика. Только бой.
- Одноранговая сеть без сервера и синхронизация «каждый считает сам» (lockstep).
- Слияние одновременных правок (CRDT). В бою один источник истины.
- Учётные записи, подбор соперников, рейтинги — на первых этапах.
- 3D-графика и нативные мобильные приложения.
- Подстройка под внутреннее устройство конкретного хоста.

## 1.4 Заинтересованные стороны

| Роль | Что важно |
|---|---|
| Мастер | Удобно вести бой за всех, вводить физические броски, править состояние, откатывать ошибки |
| Игрок | Управлять своим юнитом со своего устройства, видеть понятную картину боя |
| Автор контента | Описывать существ, предметы, эффекты и сценарии без программирования, сразу видеть ошибки |
| Разработчик движка | Добавлять правила и адаптеры, не ломая остальное; тестировать без браузера |
| Разработчик хоста | Простой и стабильный протокол встраивания, понятный результат боя |

## 1.5 Цели качества

Пять главных, по убыванию важности. Сценарии с измеримыми критериями — в [07-quality.md](07-quality.md).

| № | Качество | Что значит для нас |
|---|---|---|
| 1 | Воспроизводимость | Один и тот же журнал всегда даёт одно и то же состояние в браузере, на сервере и в тестах |
| 2 | Расширяемость | Новый адаптер или новое правило добавляются без правок ядра и приложения |
| 3 | Автономность | Бой целиком работает в одной вкладке без сети |
| 4 | Честность | Команды проверяются по правилам, скрытое не утекает к тем, кому его видеть нельзя |
| 5 | Встраиваемость | Хост запускает бой и получает результат через один документированный протокол |

## 1.6 Ограничения

| Ограничение | Почему |
|---|---|
| TypeScript для всего кода: ядро, клиент, сервер, боты | Одно ядро для всех сред |
| Ядро работает в браузере, Web Worker и Node.js | Клиент, ИИ в фоне, сервер, тесты |
| Клиент встраивается в чужие страницы через iframe | Так работают хосты |
| Внутреннее устройство хостов на архитектуру не влияет | Движок самостоятельный продукт |
| Небольшая команда | Модульный монолит вместо микросервисов, минимум инфраструктуры |

## 1.7 Допущения

- В одном бою не больше 40 юнитов и не больше 10 участников одновременно.
- Сетевая задержка в несколько сотен миллисекунд приемлема: игра пошаговая.
- Хост доверенный для своей стороны: он сам решает, какие параметры участников передать.
