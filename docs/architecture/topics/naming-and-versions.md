# Имена и версии

Как называть паки, сущности, теги, расширения и переводы и как менять версии, чтобы старые сценарии, журналы и конфигурации потребителей продолжали работать.

Обновлено 6 октября 2026.

На имена в контенте опираются сценарии, журналы боёв, манифесты оформления и конфигурации потребителей. Поэтому опубликованное имя не меняется и не исчезает молча: при переименовании остаётся псевдоним, а удалить имя можно только в новой основной версии пака. Всё, что влияет на формат данных или на ход боя, имеет свою версию. Решение записано в ADR [0010](../../decisions/0010-content-naming-and-versions.md).

## Общие правила

- Имена пишутся латиницей в нижнем регистре, слова разделяются дефисом: `fire-arrow`, `healing-potion`. Исключение — теги.
- Имя говорит, что это, а не как оно выглядит и из какой игры взято: `poison`, а не `green-cloud`.
- В имени нет версии: `archer`, а не `archer-v2`. Новая версия — это новая версия пака.

## Паки

Имя пака состоит из латинских букв в нижнем регистре, цифр и дефисов и начинается с буквы: `core`, `demo`, `northern-campaign`. Имя `core` занято стандартным паком. Имя пака входит в имя каждой его сущности, поэтому после публикации оно не меняется.

## Сущности

Полное имя сущности — `пак:имя`: `demo:archer`, `core:poison`, `northern-campaign:bridge-ambush`. Внутри своего пака префикс можно не писать, а на сущности других паков ссылаются только полным именем.

В пределах пака имя уникально для всех видов сущностей сразу: существо и эффект не могут называться одинаково. Если они связаны по смыслу, разницу показывают в имени: способность `demo:poison-spit` накладывает эффект `demo:poison`.

Файл сущности называется её именем и лежит в папке своего вида: `creatures/archer.json`, `effects/poison.json`.

## Теги

Теги — общий словарь всех паков, поэтому префикса пака у них нет. Тег пишется словами с заглавной буквы через точку, от общего к частному: `Debuff.Poison`, `Creature.Undead`, `Immunity.Mind`.

Каждый тег объявляется ровно в одном паке. Пак `core` объявляет корни, а другие паки добавляют под ними свои ветки, например `Debuff.Cold`. Если два пака объявляют один и тот же тег, проверка контента сообщает об ошибке.

## Имена внутри сценария

У сторон, юнитов, переменных и триггеров сценария локальные имена: они уникальны только внутри своего сценария. Пишутся они по общим правилам: стороны `attacker` и `defender`, юнит `archers-1`, переменная `reinforcements-arrived`. По этим именам потребитель передаёт параметры юнитов в конфигурации боя.

## Расширения

Операции, условия, варианты механик, агенты и другие расширения регистрируются в коде. Их имя — `библиотека:имя`: `rules-stdlib:damage`, `frost-mechanics:freeze`. Расширения стандартной библиотеки `rules-stdlib` в контенте можно писать без префикса: `damage`. Если два расширения регистрируются под одним именем, запуск останавливается с ошибкой.

## Переводы

Ключ перевода — имя сущности и поле через точку: `demo:archer.name`, `demo:archer.description`. Переводы лежат в папке `i18n` пака, по файлу на язык: `i18n/ru.json`, `i18n/en.json`.

## Пример

Пак кампании, который опирается на паки `core` и `demo`:

```text
northern-campaign/
  pack.json
  creatures/frost-archer.json    northern-campaign:frost-archer, наследует demo:archer
  effects/frostbite.json         northern-campaign:frostbite с тегом Debuff.Cold
  scenarios/bridge-ambush.json   стороны attacker и defender, переменная reinforcements-arrived
  i18n/ru.json                   northern-campaign:frost-archer.name — «Ледяной лучник»
```

Манифест этого пака:

```json
{
  "name": "northern-campaign",
  "version": "1.3.0",
  "formatVersion": 1,
  "engine": ">=1.0.0 <2.0.0",
  "dependencies": { "core": "^1.0.0", "demo": "^2.1.0" },
  "extensions": ["rules-stdlib"],
  "defaultLocale": "ru",
  "aliases": { "ice-archer": "frost-archer" }
}
```

Существо раньше называлось `ice-archer`. Его переименовали в `frost-archer`, а старое имя оставили псевдонимом, поэтому сценарии и журналы со старым именем работают.

## Что имеет версию

| Что | Какая версия | Когда меняется |
|---|---|---|
| Пак | Семантическая: основная, дополнительная, исправление | По правилам ниже |
| Формат файла контента | Целое число для каждого вида файла | Когда меняется структура файла этого вида. К каждой смене пишется миграция |
| Движок и библиотеки с расширениями | Семантическая | Пак указывает диапазон версий движка, с которыми работает. В журнале записаны версии кода, на котором шёл бой |
| События журнала | Целое число для каждого вида события | Когда меняется формат события. К каждой смене пишется миграция, подробнее в описании [журнала](journal.md) |
| Состояние боя | Целое число | Когда меняется формат состояния. Старые снимки отбрасываются |
| Контракт интеграции | Целое число | Когда несовместимо меняются порты или форматы для потребителей, подробнее в описании [интеграции](integration.md) |
| Протокол боя | Целое число | Когда несовместимо меняются сообщения. При подключении клиент и сервер договариваются о версии |

## Как менять версию пака

- **Исправление**, например `1.3.0` → `1.3.1`: поменялись только тексты и переводы. Они не входят в хеш контента, поэтому такое обновление можно поставить даже посреди боя.
- **Дополнительная версия**, например `1.3.1` → `1.4.0`: добавлены сущности, теги или необязательные поля, поменялись значения, например баланс. Все прежние имена работают, ничего не удалено.
- **Основная версия**, например `1.4.0` → `2.0.0`: сущность или тег удалены, псевдоним убран, у поля поменялся смысл. Паки и сценарии, которые зависят от старой основной версии, продолжают работать с ней, пока их не обновят.

Опубликованная версия пака не меняется: любая правка — это новая версия. Поэтому журнал по номерам версий всегда указывает на конкретное содержимое.

Зависимости между паками задаются диапазоном версий: `^2.1.0` значит «любая версия 2.x, начиная с 2.1.0».

Продолжить бой, откатить его или начать ответвление можно только с тем же контентом: хеш контента должен совпасть с записанным в журнале, а код — быть совместим: реализация движка та же, а основные версии её библиотек совпадают. Просматривать старый бой можно и после обновления паков: в событиях уже записаны результаты, и пересчитывать их не нужно.
